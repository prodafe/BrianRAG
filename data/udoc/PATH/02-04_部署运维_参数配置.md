## 二、参数

如果已经安装了 RmsWeb，则可以在 web 中修改参数，如果没有安装，则需要在数据库中操作这些参数。可以修改的参数如下（按照参数名称排序）：

### 初始运行时必要参数

- **map_name**: 即 RmsPath 使用的地图名称，该配置需要和 map 表中的配置相对应：
  ![输入图片说明](https://foruda.gitee.com/images/1711505690729959600/6f0041b1_13578496.png "屏幕截图")

  **name** 需要和 path_params 中 map_name 一致，**path** 为地图的位置，一般存放于 /usr/local/rms/params/maps/ 目录下。
- **path_points_range**：节点名称可用范围，1~1000 表示可以使用 p1~p1000 的节点。如果有多个区间，区间之间用英文逗号隔开，如：1~1000, 2000～5099
- **path_robot**：初始时表中可能没有 path_robot，需要手动添加，表示如果这个机器人需要去目标点需要给这个机器人发送路径，当没有 path_robot 系统不存在时会发送给所有收到状态的机器人（除了 coordinate_robot）,当 path_robot 系统存在时，服务器只会发送路径给 path_robot。
- **monitor_robot**：初始时表中可能没有 monitor_robot，如果需要配置时需要手动添加。表示需要检测这个机器人占用了哪些节点，默认只要是 path_robot 就一定是 monitor_robot。当多个区域中有公用的节点时才需要添加 monitor_robot，表示虽然该机器人不是当前 RmsPath 给发送路径，但是如果它跑到当前 RmsPath 所管辖的区域占用了节点时需要规划路径时避开。
- **cleaning_robot**: 初始时，表中可能没有 cleaning_robot，如果需要配置时需要手动添加，表示扫地机器人。
- **coordinate_robot**: 初始时，表中可能没有 coordinate_robot, 如果需要配置时需要手动添加,表示走机器人申请路权的逻辑的机器人。
- **NotifyRobotsTask**：初始时，表中可能没有 NotifyRobotsTask，如果需要配置手动添加，表示定期检查，并向附近机器人发送有关彼此状态的通知。
- **sync_to_db**: 初始时，表里可能没有 sync_to_db，需要在 UI 里显示扫地机器人位置时，需要建立或修改此参数，并配置为 1。

另外的部分参数说明如下：

- **robot_range**：机器人占用节点的范围半径，该参数也同时决定了绘制地图节点时的节点间隔大小。一般该值设置为机器人的宽度。假设该值为 800mm，如果节点之间的距离小于 800mm，则机器人走到任何一个点，另一个点也会被占用，所以这两个点其中一个点就是多余的，需要将节点进行稀疏化；如果节点之间的距离大于 800mm*2=1.6m，那么如果机器人走到两个节点正中间的时候，该机器人一个节点都没有占用，此时前后两个节点都是可以被其他机器人使用的，就有可能造成拥堵。所以地图节点的间距 L 需要满足条件：robot_range < L < 2 x robot_range。新添加了 use_direction 参数，表示在占用节点时是否考虑机器人的朝向以及根据机器人真正的模型进行节点的占用，与其配合使用的参数有 robot_length_front_mm, robot_length_rear_mm, robot_width_mm。
- **path_robot**: 只有当现场有多台 RmsPath 服务时，需要给所有的机器人配置 path_robot，用来区分机器人属于哪一个 RmsPath 服务，当只有一个 RmsPath 服务时，不需要配置 path_robot，如果已配置此参数的现场，需要对所有的小车配置 path_robot 或删除所有 path_robot
