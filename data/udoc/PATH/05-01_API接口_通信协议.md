## 一、概述

本文件详述了机器人系统中的通信协议，主要包括 `sendPath` 协议、`sendBlockMessage` 协议和 `request` 协议的格式与使用方法。文档重点说明了各类 UDP 消息中的字段定义与含义，涵盖指令下发、路径控制、状态请求等通信场景，为实现系统间高效稳定的数据交互提供参考依据。

## 二、Send Path 协议

### 2.1 服务器 → 机器人

一个UDP包包含一个Json Object。Json Object包含下列字段

路径下发

| 字段名                         | 数据类型    | 可能的值                                                                                                                   | 描述                                                                       |
| --------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| cmd                         | String  | "path"                                                                                                                 | 命令类型                                                                     |
| goal                        | String  | "DockC"                                                                                                                | 目标位置的标识符，例如"DockC"代表一个充电站位置                                              |
| stamp                       | String  | "20240326-105455"                                                                                                      | 时间戳，格式为"年月日-时分秒"                                                         |
| id                          | Number  | 17114216959                                                                                                            | 唯一识别ID，用于追踪特定的命令或者路径                                                     |
| path                        | String  | "-12411,92595\|-12444,95542\|-12447,97529,180"                                                                         | 路径坐标，由多个坐标点组成，每个点用"\|"分隔,除了Goal意外都为两个坐标代表x值,y值，goal点为三个坐标组成，最后一个坐标代表停放角度 |
| narrow                      | Boolean | true or false                                                                                                          | 表示那个位置是不是库位，数组长度跟points一样。true就代表对应点是库位。为了向前兼容没有narrow的话就默认全是false       |
| points                      | Array   | ["p218","p219","p220"]                                                                                                 | 路径点的数组，每个元素是一个点的标识符，如"p218"                                              |
| posture                     | Array   | ["",""]                                                                                                                | 姿态数组，与points数组除第一个点外的点对应的姿态信息，可能为空字符串或姿态参数                               |
| final                       | Boolean | false                                                                                                                  | 是否为最终路径点，true或false                                                      |
| name                        | String  | "uBot-004"                                                                                                             | 接受UDP包的机器人的名字                                                            |
| nextPoint                   | Json    | \{"name":"p221", "pose":"-12452,99550,-90", "posture":"..."\}                                                          | 路径上未分配的下一个节点信息                                                           |
| **clearances\[clearance\]** | Array   | \[null, {...}\]                                                                                                        | null 或 json，表示线段的避障参数配置列表，n个点有对应的 n-1 个避障参数                              |
| clearance                   | Json    | {"mode_a": {"front":100,"back":100,"left":100,"right":100}, "mode_b": {"front":100,"back":100,"left":100,"right":100}} | 表示单独的避障参数配置                                                              |
|                             |         |                                                                                                                        |                                                                          |

根据此协议，服务器可以生成以下json并发送给机器人

```json
{
    "cmd": "path",
    "goal": "DockC",
    "stamp": "20240326-105455",
    "id": 17114216959,
    "path": "-12411,92595|-12444,95542|-12447,97529",
    "points": [
        "p218",
        "p219",
        "p220"
    ],
    "narrow": [
        false,
        true,
        false
    ],
    "posture": [
        "",
        ""
    ],
    "final": false,
    "name": "uBot-004",
    "nextPoint": {
		"name": "p221",
		"pose": "-12452,99550,-90",
		"posture": "..."
	},
	"clearances": [
		null,
		{
		  "mode_a": {
			"front": 100,
			"back": 100,
			"left": 100,
			"right": 100
		  },
		  "mode_b": {
			"front": 100,
			"back": 100,
			"left": 100,
			"right": 100
		  }
		}
	]
}
```

## 三、send Block message 协议

### 3.1 服务器 → 机器人

| 字段名 | 数据类型 | 可能的值      | 描述                                     |
| ------ | -------- | ------------- | ---------------------------------------- |
| id     | Number   | "17115244445" | 唯一的消息或命令标识符                   |
| cmd    | String   | "info"        | 命令类型，"info"表示请求或提供信息的命令 |
| msg    | String   | "ubot-001"    | 阻挡的机器人                             |
| name   | String   | "ubot-002     | 接受UDP的机器人                          |

以ubot-001阻挡ubot-002为例，此时应向ubot-002发送UDP包，用来表示机器人被ubot-001阻挡
此时服务器会发送以下json给ubot-002

```json
{
"id" :17115244445,
"cmd": "info",
"msg": "Bot300-001",
"name": "Bot300-002"
}
```

## 四、Request 协议

- 当前 request 类型：
    - point：机器人申请锁点，其他机器人不得分配该点位
    - turn_point: 机器人申请旋转坐标和半径，path 进行该范围内的锁点，其他机器人不得分配该点位
    - turn：机器人请求在某坐标旋转，附近点位（一个阈值的距离内）不批准其他机器人的 turn 请求
- 在发送 request 的阶段
    - 若收到服务器的回复，无论结果是true成功还是false失败，下一次发送新的请求要创建新的 id，避免出现在同一个id上，返回了false，后续又返回true
    - 若没有收到服务器的回复，可用同样的 id 进行重发
    - 对已经成功的 request id 进行记录，若服务器收到的请求 id 已经记录 true，不进行计算，直接返回 true
    - 一台机器人同一时间只能有一个记录在系统的成功请求，在释放 release 上一个成功请求之前，对于新的 request id，一律返回 false
- 在发送 release 的阶段
    - 注意发送 release 的时间节点，是机器人完成了相关的操作，确认可释放相关请求
    - 若没有收到服务器的回复，则用同样的 id 进行重发，确保收到服务器的回复
    - 收到 release 请求的服务器，会把之前成功的 request 释放
    - release 始终会收到 true
- point/turn_point 和 turn 分别设有 timeout，过了 timeout 之后自动释放请求
- 若机器人处在 disable 或者 lost 的状态，释放成功的请求

### 4.1 RequestPoint

- 注意：此处申请锁点的操作是整个集合同时进行的，若点集合太大，总是有机器人占用任意一个点，会导致难以锁点成功，建议：
  （1）点集合设置较小，易于抢占，如：机器人倒退重入机台时
  （2）点集合较大时，结合单机区的使用，确保区域内只有一辆机器人，如：外部机器人占用公共区域时

#### 机器人 → 服务器

| 字段名 | 数据类型          | 示例                              | 描述                   |
| ------ | ----------------- | --------------------------------- | ---------------------- |
| name   | String            | "ubot-001"                        | 申请节点的机器人名字   |
| action | String            | "request_point" / "release_point" | 动作类型               |
| id     | Number            | 1234567890                        | 唯一的消息或命令标识符 |
| point  | List `<String>` | ["p1", "p2", "p3"]                | 申请和释放的节点列表   |

```json
// request point
{
    "name": "ubot-001",
    "action": "request_point",
    "id": 1234567890,
    "point": ["p1", "p2", "p3"]
}

// release point
{
    "name": "ubot-001",
    "action": "release_point",
    "id": 1234567890
 }
```

#### 服务器 → 机器人

| 字段名 | 数据类型 | 示例                              | 描述                   |
| ------ | -------- | --------------------------------- | ---------------------- |
| action | String   | "request_point" / "release_point" | 申请类型               |
| id     | Number   | 1234567890                        | 唯一的消息或命令标识符 |
| result | boolean  | true / false                      | 申请/释放结果回复      |

```json
// request point response
{
    "action": "request_point",
    "id": 1234567890,
    "result": true
}

// release point response
{
    "action": "release_point",
    "id": 1234567890,
    "result": true
}
```

### 4.2 RequestTurnPoint

#### 机器人 → 服务器

| 字段名 | 数据类型 | 示例                                        | 描述                             |
| ------ | -------- | ------------------------------------------- | -------------------------------- |
| name   | String   | "ubot-001"                                  | 申请节点的机器人名字             |
| action | String   | "request_turn_point" / "release_turn_point" | 动作类型                         |
| id     | Number   | 1234567890                                  | 唯一的消息或命令标识符           |
| x      | double   | 500                                         | 申请进行旋转位置的坐标x，单位 mm |
| y      | double   | 500                                         | 申请进行旋转位置的坐标y，单位 mm |
| radius | int      | 1000                                        | 机器人的旋转半径，单位 mm        |

```json
// request turn point
{
    "name": "ubot-001",
    "action": "request_turn_point",
    "id": 1234567890,
    "x": 500,
    "y": 500, 
    "radius": 1000
}

// release turn point
{
    "name": "ubot-001",
    "action": "release_turn_point",
    "id": 1234567890
 }
```

#### 服务器 → 机器人

| 字段名 | 数据类型 | 示例                                                           | 描述                   |
| ------ | -------- | -------------------------------------------------------------- | ---------------------- |
| action | String   | "request_turn_point" / "release_turn_point"                    | 申请类型               |
| id     | Number   | 1234567890                                                     | 唯一的消息或命令标识符 |
| result | boolean  | true / false                                                   | 申请/释放结果回复      |
| msg    | String   | "Accept request_turn_point [p1], id: 1234567890 from ubot-001" | 处理消息参考           |

```json
// request turn point response
{
    "action": "request_turn_point",
    "id": 1234567890,
    "result": true
    "msg": "Accept request_turn_point [p1], id: 1234567890 from ubot-001"
}

// release turn point response
{
    "action": "release_turn_point",
    "id": 1234567890,
    "result": true
}
```
