## 一、概述

该协议主要用于单方面通知机器人某些信息，使用 UDP 进行通信，数据包格式如第二章所述。

## 二、数据包格式

数据包为 json 格式字符串，里面必须要包含的 key 为 cmd 和 id，如下表所示：

| **Key** | **说明**   | **类型** | **举例** |
| ------- | ---------- | -------- | -------- |
| **cmd** | 命令、类别 | String   | “rms”    |
| **id**  | 序列号     | Integer  | 13423423 |

1. 所有的 key 最好是小写字母，`cmd`和`id`必须是小写字母。
   2) 数据长度不能超过 10240 个字节。
   3) `cmd`对应的值类型为 string，表示数据包的类别，机器人端会通过该值来区分数据包，将不同类别的数据包存储到不同的位置，如果`cmd`相同，则数据包之间会互相覆盖。
   4) `id`对应的值类型为 long long int，即 integer，取值范围为-9223372036854775808~9223372036854775807，表示 UDP 包的顺序，`id`比较大的数据包会覆盖`id`比较小的数据包。`id`最好与时间绑定，防止重启后`id`清零造成一段时间内机器人拒绝数据包的情况。另外，因为机器人端接收 UDP 数据包时间间隔大约是 100ms，所以，最好是每 100ms 发一次包，`id`变化一次，如果`id`变化频率超过 10 次/秒，则会导致`id`的浪费。综上所述，建议采用系统时间(毫秒)/100 作为`id`的值。

举例来说，RMS 发送给机器人的 ip 数据包类似以下格式：

```json
{
	"cmd": "rms",
	"id": 12341234,
	"ip": "192.168.1.2"
}
```
