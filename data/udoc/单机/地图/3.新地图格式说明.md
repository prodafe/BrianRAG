## 1. 概述

软件系统各个部分对于地图的需求不同，但又有一致性的要求，需要对地图进行进一步丰富，并且保证调度/单机的一致性，对地图作出以下修改：

1. 地图的拆分：不同的模块可以使用地图拆分后的模块，减少加载时对于内存、CPU 的占用，保证无需重启及能动态切换路径地图；独立定位地图，减弱其他模块对于定位地图的感知；
2. 一致性保证：确定地图的同步机制，使用 MD5 值强制进行校验；单机保存多个地图，支持实时切换加载，由调度触发确定当前使用哪张地图，单机和调度同步确定地图的一致性；
3. 地图编辑：在地图编辑保存阶段即生成兼容 umcl-map2 的地图，可以生成拆分后的子图、编辑子图间的关联节点信息，将多张子图和地图的拓扑结构信息上传到单机；

## 2. 地图文件结构（兼容旧版单地图文件）

地图统一存放目录为（包括地图服务器和单机）：`/usr/local/maps/`，存放的地图文件为zip压缩包，文件命名格式为`地图名称.time[14位].地图类型[topo1/umcl3].zip`，示例：
- 拓扑地图：`A.20251029225513.topo1.zip`
- 旧版单地图文件：`A.20251029225513.umcl3.zip`

压缩包内的文件结构如下：
```
A.20251029225513.topo1.zip/
├── map.json             //机器人当前所在子图，切换地图时更新该文件，详细格式说明见下方
├── map_graph.json       //拓扑节点地图，包含所有子地图的文件信息和关联节点信息，详细格式说明见下方
├── sub_map1.json       //导航子地图，可有多个
├── sub_map2.json
...
├── loc_map1.pgm        //定位子地图，可有多个
├── loc_map2.pgm
...

```

### map.json格式
map.json 中的内容如下所示：

```json
{
    "name":"A",  //机器人当前所在子图名称
	"suffix": "json",
	"md5": "ABCDEFGHIJKLM123"
}
```

### map_graph.json格式
map_graph.json 中的内容如下所示：

```json
{
    "Header": "umcl-topo",
    "SubMaps":[      //所有导航子地图文件信息
        {
            "name":"A",
            "suffix": "json",

        },
        {
            "name":"B",
            "suffix":"pgm",

    ],
    "LocMaps":[     //所有定位子地图文件信息

            "name":"A",

        {
            "name":"p1.2",
```

## 3. 地图启用
地图启用前需先将地图文件解压到`单机程序配置目录/map/`目录下，解压后目录名称仅保留地图名，并在`单机程序配置目录/map/map.json`文件内配置地图名称。示例如下

```
/usr/local/urobot/params/map/map.json
{
    "name":"A"
}


/usr/local/urobot/params/map/
A/
├── map_graph.json
├── map.json
├── 1.json
├── 2.json
├── 3.pgm
B/
├── map_graph.json
├── map.json
├── 1.json
...

```

## 4. 地图格式
- 定位子图：不限格式,只需要在 `map_graph.json` 能索引到即可。目前针对 2D 地图，为 umcl-map3 版本中 MapRes,MaxPose,MinPose,NumLines,NumPoints,ObsPoints 和 ObsLines 中的部分;
- 导航子图：umcl-map3 版本中 Binding 和 Objs 的部分;

### 分项描述

-   Header: 为地图类别描述，表示版本等信息: umcl-map 不包含 connections, umcl-map2 包含 connections 信息
-   MapRes: 为地图分辨率，单位为 mm/pixel，即地图中的最小格边长为 20mm
-   MaxPose 和 MinPose: 地图为二维笛卡尔坐标系地图(x 轴正方向为正右方，y 轴正方向为正上方)，MaxPose 和 MinPose 表示能包含地图中所有点的矩形框的右上方和左下方点的坐标
-   NumLines: 表示 ObsLines 数组中线段的个数
-   NumPoints: 表示 ObsPoints 中点的个数
-   ObsPoints: 表示地图中的障碍物点，内部每个数组表示地图某一列的点的信息，格式为[x, y1, y2, y3...]，即第一个元素表示 x 列，后续的数值表示点的 y 坐标，如[1, 0, 5, 10080]表示 3 个点，坐标分别是[1,0],[1,5],[1,10080]
-   ObsLines: 表示地图中的障碍物线段，格式为"x1 y1 x2 y2"，表示线段的两个端点坐标
-   Objs: 用于表示地图中绘制的目标点、线段、区域等信息，Objs 为 json 对象，内部对象的 key 值为元素的种类，如目标点(Goal)，带方向的目标点(GoalWithHeading)，内部对象的值都是数组，数组中的每个元素为具体的元素信息，基本格式如下所示（仅列举一些常用的元素 key）：

    ```json
    {
    	"name": "p1",
    	"pose": "x y theta",
    	"points": "x1 y1 x2 y2",
    	"costs": [1, 1],
    	"vertex": "p5718 p7302"
    }
    ```

    -   name: 元素名称，如目标点的名称 A，或者路径节点的名称 p1 等，区域和线段可能没有名称
    -   pose: 元素的位置，如目标点、节点的坐标，线段和区域可能没有 pose
    -   points: 一般仅用于线段表示两个端点的坐标，或用于表示矩形区域左下角和右下角两个点的坐标
    -   vertex: 仅用于路径节点，表示 p1 可以到达 p5718 和 p7303
    -   costs: 仅用于路径节点，表示 p1 到 p5718 的代价为 1，p1 到 p7302 的代价为 1
    -   postures: 用于表示当前节点到下一个节点时的姿态，以':'间隔
    -   connections: umcl-map2版本加入的信息,将边的信息单独列出作为一个数组


目前已知的各个机型支持的姿态信息如下所示:

-   差速
    - F：前向移动
    - B：后向移动
    - O：全向移动

-   双舵轮
    - AH：车头运行
    - AT：车尾运行
    - AL：车左方平移
    - AR：车右方平移
    - BH 或 BT：车头或车尾运行
    - BL 或 BR：车左方或右方平移
    - O：车全方向平移

-   叉车
    - F：前向移动
    - B：后向移动
    - O：全向移动

-   转盘
    - K90：姿态保持到 90 度（数字可变，范围-180）
    - R0：转盘旋转到机器人的 0（数字可变，范围-180）
    - M-38: 转盘旋转到地图的-38 度（数字可变，范围-180）
