## 1.第三层地图与全图的关系

第三层地图为全图的一部分，地图编辑客户端保存地图时全图会保存全部元素，另外会生成另一个 `同名-3.json` 文件。为了保证原地图文件包含所有的信息，需要对原地图进行扩展，扩展的元素在后续章节描述，当前章节只用示例说明整图与第三层地图的关系。

如下面这个地图 `A.json`

```json

  "MaxPose": "10260 10080",
  "MinPose": "0 0",
  "NumLines": 0,
  "NumPoints": 4,
  "Binding":
  [
    { "from": "p1", "to": "p2", "type": "type1" },

  ], 
  "Objs":
  {

    "Goal":
    [
      {"name": "D", "pose": "2241 7920 0.00" }
```

同步生成的`A-3.json`文件如下所示：

```json
{
    "Infras": {
      "Wall":[], "Hydrant":[], "Pillar":[], "Desk":[]
    },
    "Landmarks": {
      "Goal":[], "HeadingGoal":[], "Park":[], "Dock":[], "Storage":[], "PathPoint": []

      "OneWay":[], "2W1L":[], "2W2L":[]

```

即 `A-3.json` 文件内容为 `A.json` 文件中 `Overlay` 元素内部的所有内容，其中，由于 `Goal`, `HeadingGoal`, `Park`, `Dock`, `PathPoint` 这些元素与第二层地图中的 `Objs` 中的元素是重复的，因此在整图文件 `A.json` 中的 `Overlay` 中不再重复生成，但是在同步生成 `A-3.json` 文件时需要放入 `Landmarks` 中。

## 2.元素分类

第三层地图为完全手动绘制的元素地图，分类如下:

-   基础设施(Infras): 墙面(Wall)，消防栓(Hydrant)，立柱(Pillar)，办公桌(Desk)等
-   地标(Landmarks): 目标点(Goal)，带方向目标点(HeadingGoal)，停车点(Park)，充电点(Dock)，库位(Storage)，路点(PathPoint)
-   通道(Lanes): 单行道(OneWay), 双向单车道(2W1L), 双向双车道(2W2L)...
-   区域(Areas): 缓冲区(Buffer)
-   设备(Devices): 线体(ProductionLine),脱胶(Debonding),切片(Slicer),晶拖(CrystalHolder),...

## 3.元素属性

每个元素表达的规则如下:

-   name: 表示元素的名称，支持中文，至少同一类元素中 name 具有唯一性
-   pose: 表示元素的中心点坐标，内部为三个 double 值"x y t"，中间用空格隔开，xy 为全局二维坐标，单位为毫米, t 一般用来表示元素的方向，单位为角度, 范围为[-180,180)，如目标点朝向
-   points: 用于表示线段元素或矩形元素，内部为四个 double 值 "x1 y1 x2 y2"，分别表示起点和终点的二维全局坐标，中间用空格隔开，单位为毫米，起点和终点的规则是：如果没有方向要求，那么 x~起点~(x~1~) <= x~终点~(x~2~), y~起点~(y~1~) <= y~终点~(y~2~), 如果起点和终点是有方向的，如 OneWay 表示道路行驶的方向是从起点到终点，那么可以不用遵循这个要求。
-   polygon: 用于表示元素的多边形外框,必须与 pose 配合使用，polygon 中的多个坐标值表示的是相对于 pose 的局部坐标,pose 为该元素中心的全局坐标,polygon 中的多个坐标点依次连接，末尾坐标与首坐标相连，形成一个闭合的多边形。

为了防止元素中同时包含`pose`,`points`,`polygon`而导致绘制图形的歧义,对于每个元素几何图形绘制优先级定义为 `pose+polygon > points > pose`, 即元素内如果有 `polygon+pose` 值，则使用中心坐标+局部边框坐标的方式绘制元素, 如果没有`polygon`，则使用全局 `points` 坐标值绘制矩形和线段, 只有没有大小的元素，如目标点才只会设置 `pose` 值。

## 4.示例

下面为一个示例:

```json
{
	// 基础设施
	"Infras": {
		// 墙面: 线段表示
		"Wall": [{ "points": "x1 y1 x2 y2" }, { "points": "x1 y1 x2 y2" }],
		// 消防拴: 矩形框表示，可能需要标注名称
		"Hydrant": [{ "name": "H1", "points": "x1 y1 x2 y2" }],
		// 立柱: 矩形框表示
		"Pillar": [{ "points": "x1 y1 x2 y2" }],
		// 办公桌: 矩形框表示，可能需要标注名称
		"Desk": [{ "name": "D1", "points": "x1 y1 x2 y2" }]
	},
	// 地标，几乎都是从二层地图copy过来
	"Landmarks": {
		// 无方向目标点：全局坐标+名称，t为0
		"Goal": [{ "name": "A", "pose": "x y 0" }],
		// 带方向目标点：全局坐标+名称, t取值范围[-180,180)
		"HeadingGoal": [{ "name": "B", "pose": "x y t" }],
		// 停车点
		"Park": [{ "name": "ParkA", "pose": "x y t" }],
		// 充电点，需要再在充电点周围添加区域显示
		"Dock": [{ "name": "chargeA", "pose": "x y t" }],
		// 库位: 全局坐标+名称+容量
		"Storage": [{ "name": "CP01", "pose": "x y t", "capacity": 1 }],
		// 路径点
		"PathPoint": [
			{ "name": "p1", "pose": "x y t", "vertex": "p2", "costs": [1] },
			{ "name": "p2", "pose": "x y t", "vertex": "p1", "costs": [1] }
		]
	},
	// 通道
	"Lanes": {
		// 单行道(1W1L): 名称+全局坐标带方向线段+宽度
		"OneWay": [{ "name": "Path1", "points": "x1 y1 x2 y2", "width": 1000 }],
		// 双向单车道(2W1L)：需要预防对向行驶，名称+全局坐标线段(不需要方向)+宽度
		"2W1L": [{ "name": "Path2", "points": "x1 y1 x2 y2", "width": 1000 }],
		// 双向两车道(2W2L): 等于两个反向的单行道，宽度x2
		"2W2L": [{ "name": "Path3", "points": "x1 y1 x2 y2", "width": 2000 }]
	},
	// 区域
	"Areas": {
		// 缓冲区
		"Buffer": [{ "name": "BufEmpty", "points": "x1 y1 x2 y2" }]
	},
	// 设备
	"Devices": {
		// 产线：名称+中心坐标+模型局部坐标+是否翻转
		"ProductionLine": [{ "name": "L05", "pose": "x y t", "polygon": "x1 y1 x2 y2 x3 y3", "flip": false }],
		// 脱胶
		"Debonding": [{ "name": "DP1", "pose": "x y t", "polygon": "x1 y1 x2 y2 x3 y3", "flip": false }],
		// 切片
		"Slicer": [],
		// 晶托
		"CrystalHolder": []
	}
}
```

## 5.模型

另外，客户端内部需维护一个模型文件 `model.json` 对各个类别的元素进行详细说明,用于保存一些模型的缺省参数值，在导出第三层地图时，需完整导出所有参数内容。

示例如下:

```json
{
  "Storage": {
    "capacity": 1
  },
  "ProductionLine": {
    "color": "#000000",
    "polygon": "x1 y1 x2 y2 x3 y3"
  },
  "Debonding": {
    "color": "#123456",
    "polygon": "x1 y1 x2 y2 x3 y3"
  },
  ...
}
```

地图中的元素的属性的优先级高于模型的默认属性。
