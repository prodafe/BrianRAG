## 同步机制

### 1.单机使用

单机上地图参数的文件结构需要修改，原文件结构为:

```
urobot/params/map/
	map.json
	A.json
	B.json
```

需要修改为:

```
urobot/params/map/
	map.json
	A-20250101142552-123DEF.json
	B-20250102140000-xxxxxx.json

```

原 map 目录下的 map.json 内容为：

```json
{
	"name": "A.json"
}
```

需要将"name"从地图文件路径改为地图名称，md5 为`name.time.md5.json`地图文件的 md5 值:

```json
{
	"name": "A",
	"md5": "123DEF"
}
```

#### 2.1.1. 兼容性操作

启动时根据`name`和`md5`找到对应的地图文件进行加载，如果只包含`name`，说明本机地图尚未更新到新地图格式，需要本机内部做兼容性修改:

-   按照原 map.json 加载 A.json 地图，生成对应的`A.time.md5.json`新地图
-   修改 map.json 中 name 和 md5 字段
    这样就能保证本机地图已经切换成了新地图。

#### 2.1.2. 加速操作

如果考虑到后续定位和导航针对性加载子图，可以同时生成`A.time.md5.loc.json`和`A.time.md5.nav.json`子图，**注意:此处不能修改原地图文件内容**。

### 2.2. 地图上传

1. 通过客户端保存成`A.time.md5.json`文件,当前版本不在内部增加`SubMapXXX`字段，
2. 通过专用的地图上传上传 zip 压缩包到/temp 目录，上传后解压，通过 md5 值对文件进行校验，成功后通过 mv 指令移动，`如果需要的话可以再次进行md5校验?`。

### 2.3. 与调度的同步(path)

交通管制由路径管制服务(planner)收取机器人(robot)状态，然后下发路径(path)的方式进行，整个更新的过程如下所示：

```plantuml

== 切换前,地图md5==123DEF ==
Robot -> Path: status:{map:123DEF}
...
Path -> Robot: path:{map:123DEF}
...
== 切换时,地图123DEF->ABCDEF ==
Robot -> Path: status:{map:123DEF}
Path -> Path: 切换地图到ABCDEF,重启

activate Path #DarkSalmon
Path -> Robot: **切换通知**path:{map:ABCDEF}

activate Robot #DarkRed
Robot -> Path: status:{map:123DEF}
Path -> Robot: **切换通知**path:{map:ABCDEF,INVALID_MAP}
Robot -> Robot: 查找本地md5为ABCDEF的地图
Robot -> Path: status:{map:123DEF}
Path -> Robot: path:{map:ABCDEF,INVALID_MAP}
Robot -> Robot: 内部重新加载地图
Robot -> Path: status:{map:ABCDEF}
deactivate Path #DarkSalmon
deactivate Robot
Path -> Robot: path:{map:ABCDEF}
== 切换后,地图md5==ABCDEF ==
...
Robot -> Path: status:{map:ABCDEF}
...
Path -> Robot: path:{map:ABCDEF}
...
```

#### 2.3.1. 单机 status 的修改

单机在原有的 UDP-status 包中增加当前使用的小车的 md5 值，可以按时间间隔发送，不一定每一个包中都带上，可以 10 秒发送一次，降低网络负载。

正常 UDP-status 包如下：

```json
{
	"name": "bot-001",     // str，机器人名称
	"ip": "192.168.1.2",   // str，机器人ip
	"status": "",          // str，机器人状态
	"mode": "",            // str，机器人工作模式
	"motor_state": 1,      // int, 1使能 or 0急停
	"x": 0,                // int
	"y": 0,                // int
	"theta": 0,            // long，朝向，角度值deg(-180,180]
	"vf": 0,               // int，线速度, mm/s
	"vr": 0,               // int，角速度, deg/s
	"battery": 100,        // int，电量, [0-100]
	...
}
```

增加 md5 值的 status 包如下：

```json
{
	"name": "bot-001", // str，机器人名称
	"ip": "192.168.1.2", // str，机器人ip
	"status": "", // str，机器人状态
	"mode": "", // str，机器人工作模式
	"motor_state": 1, // int, 1使能 or 0急停
	"x": 0, // int
	"y": 0, // int
	"theta": 0, // long，朝向，角度值deg(-180,180]
	"vf": 0, // int，线速度, mm/s
	"vr": 0, // int，角速度, deg/s
	"battery": 100, // int，电量, [0-100]
	"map": "123EDF" // str，前三位+后三位
}
```

#### 2.3.2. path 的修改

path 在每次给小车重新规划路径时(wholepath)，向小车发送当前地图的 md5 码值（前三位+后三位）

原发送的消息如下：

```json
{
	"cmd": "path", // 指令，必须为"path"
	"goal": "A", // 最终目标点名称
	"stamp": "20240326-105455", // 时间戳
	"id": 17114216959, // 数据包id，必须为递增long型数字
	"path": "1,2|3,4|...", // 坐标路径，节点坐标之间用'|'间隔，坐标值之间用','间隔
	"points": ["p218", "p219", "p220"], // 名称路径
	"final": true // 最后一个点是否为最终目标点的坐标
}
```

增加地图信息的消息如下：

```json
{
	"cmd": "path", // 指令，必须为"path"
	"goal": "A", // 最终目标点名称
	"id": 17114216959, // 数据包id，必须为递增long型数字
	"path": "1,2|3,4|...", // 坐标路径，节点坐标之间用'|'间隔，坐标值之间用','间隔
	"points": ["p218", "p219", "p220"], // 名称路径
	"final": true, // 最后一个点是否为最终目标点的坐标
	"map": "123DEF" // path当前使用的地图的md5值的"前三位+后三位"
}
```

如果 path 检查到小车的 status 包中地图的 md5 值(前三位+后三位)不一致，则下发路径通知小车，只需要修改`goal`对应的值为`INVALID_MAP`(与`UNKNOWN_GOAL_FOR_INVALID_STATE`类似):

```json
{
   "cmd": "path",
   "id": 递增id,
   "goal": "INVALID_MAP",
   "map": "123DEF",
   ...
}
```

**在下发`INVALID_MAP`的同时，需要一直发送当前 path 使用的地图信息，便于单机重新加载地图**

#### 2.3.3. 单机切换地图

单机在接收路径时，如果当前使用地图 md5 值与 path 发送的路径包中的 md5 值相同，则与原来的处理方法一样，不做任何修改；如果监测到 md5 值不一致，单机需要直接动态加载对应地图的 nav 子图（无需重启单机程序），如果子图找不到，需要加载整张地图，加载完成后再根据对应的路径跟随。在此期间，因为 md5 值始终对应不上，path 也不会给小车发送具体的路径。

具体搜索地图的过程如下：

```plantuml

start
:robot当前地图md5值123DEF;
:robot收到新地图md5值ABCDEF;
:robot从当前params/map目录下查找是否存在对应md5值的整图和子图(名称.时间.md5值中md5值的"前三位+后三位"与ABCDEF一致);
if (找到了整图) then
	if (找到了子图) then
		:加载导航子图;
	else (没有找到子图)
		:加载整图;
	endif
	:修改map.json中的数据(name+md5);
	:设置内部使用的地图md5值为ABCDEF;
else (没找到整图)
	:不做任何动作;
endif
stop

```

#### 2.3.4. 地图的切换注意点

path 只是通知了要切换导航地图，定位地图是否需要同步切换需要根据启动时定位模块记录的地图 md5 值与当前使用的地图 md5 值进行比较，选择合适的时机切换内存中的定位地图。
如果定位地图不动态切换，那么在下次单机程序启动时也会使用新地图(因为 map.json 中地图 md5 值已经被修改)。
