## 1.地图版本

### 1.1. 初版(umcl-map)
地图是一个 json 文件，内部包含地图中的障碍物点、线，绘制的物体(目标点、节点、区域)等信息，一个的比较完整的地图格式如下所示:

```json
{
    "Header": "umcl-map",
    "MapRes": 20,
    "MaxPose": "10260 10080",
    "MinPose": "-100 40",
    "NumLines": 0,
    "NumPoints": 4,
    "Objs": 
    {
        "GoalWithHeading": 
        [
		    {
                "name": "C",
                "pose": "8111 8441 0.00"
            },
            {
                "name": "A",
                "pose": "1650 1546 0.00"
            }
        ],
        "Goal": 
        [
	        {
                "name": "D",
                "pose": "2241 7920 0.00"
            }
        ],
        "PathPoint":
        [
	        {
		        "costs": [1, 2],
		        "name": "p5712",
                "pose": "-6123 674 0",
                "vertex": "p5718 p7302"
            }
        ]
    },
    "ObsPoints": [[1, 0, 5, 10080],...],
    "ObsLines": ["2241 7920 2241 8000",...]
}
```

- Header: 为地图类别描述，表示版本等信息: umcl-map为版本号，表示第一版地图格式
- MapRes: 为地图分辨率，单位为 mm/pixel，即地图中的最小格边长为 20mm
- MaxPose 和 MinPose: 地图为二维笛卡尔坐标系地图(x 轴正方向为正右方，y 轴正方向为正上方)，MaxPose 和 MinPose 表示能包含地图中所有点的矩形框的右上方和左下方点的坐标
- NumLines: 表示 ObsLines 数组中线段的个数
- NumPoints: 表示 ObsPoints 中点的个数
- ObsPoints: 表示地图中的障碍物点，内部每个数组表示地图某一列的点的信息，格式为[x, y1, y2, y3...]，即第一个元素表示 x 列，后续的数值表示点的 y 坐标，如[1, 0, 5, 10080]表示 3 个点，坐标分别是[1,0],[1,5],[1,10080]
- ObsLines: 表示地图中的障碍物线段，格式为"x1 y1 x2 y2"，表示线段的两个端点坐标
- Objs: 用于表示地图中绘制的目标点、节点、线段、区域等信息，Objs 为 json 对象，内部对象的 key 值为元素的种类，如目标点(Goal)，带方向的目标点(GoalWithHeading)，内部对象的值都是数组，数组中的每个元素为具体的元素信息
	- name: 元素名称，如目标点(Goal)的名称 A，或者路径节点(PathPoint)的名称 p1 等，区域和线段可能没有名称
	- pose: 元素的位置，如目标点、节点的坐标，线段和区域可能没有 pose
	- points: 一般仅用于线段表示两个端点的坐标，或用于表示矩形区域左下角和右下角两个点的坐标
	- vertex: 仅用于路径节点，表示 p1 可以到达 p5718 和 p7303
	- costs: 仅用于路径节点，表示 p1 到 p5718 的代价为 1，p1 到 p7302 的代价为 2

### 1.2. 第二版(umcl-map2)

为了解决路网节点信息缺失的问题，统一增加各个机型在路线上的姿态信息，在第一版(umcl-map)的基础上有以下修改:

1) Header: 从umcl-map改为umcl-map2
2) 增加Binding信息: 表示节点绑定信息，如下示例中绑定信息表示从p1到p2的有向线段绑定类型为type2，用于steer类型的机器人。

```json
	"Binding": 
	[
		{
            "from": "p1",
            "to": "p2",
            "type": "type2",
            "robot": "steer"
        }
    ]
```

3) 增强PathPoint节点信息:

原有的PathPoint增加postures信息(临时解决方案):
```json
	"postures": "F::HF F:HF:HF",
```
- postures: 用于表示当前节点到下一个节点时的姿态，以':'间隔，分别表示"差速车行驶姿态:舵轮全向车行驶姿态:叉车行驶姿态"，姿态使用字符串表示，含义如下：
		1) 差速车
			- F：前向移动
			- B：后向移动
			- O：全向移动
		2) 双舵轮全向车
			- AH：车头运行
			- AT：车尾运行
			- AL：车左方平移
			- AR：车右方平移
			- BH或BT：车头或车尾运行
			- BL或BR：车左方或右方平移
			- O：车全方向平移
		3) 叉车
			- F：前向移动
			- B：后向移动
			- O：全向移动

增加connections字段，用于详细描述边的属性：

```json
	"connections":
	[
		{
			"name":"p5718",
			"cost":1,
			"posture": "F::HF",
			"type":1,
			"x1":-1200,
			"x2":-1200,
			"y1":0,
			"y2":0
		},
		{
			"name":"p7302",
			"cost":2,
			"posture": "F:HF:HF",
			"type":1,
			"x1":-1200,
			"x2":-1200,
			"y1":0,
			"y2":0
		}
	]
```

如 `p5712` 这个节点的connections属性定义如上，connections数组中有两个元素，表示有两个出边，可分别到达 `p5718` 和 `p7302`。以 `p5718` 为例，该元素内部有一些信息是与外部相同的，如`"cost":1`与外部的`"costs": [1, 2]`中的第一个元素1表达的含义是一样的，表示`p5712-p5718`这条边的经过代价为1；posture信息也一样，与外部的postures信息是相同的；增加connections数组的目的是为了扩展边的属性，外部的信息保留是为了兼容初版地图(umcl-map)。

扩展后的PathPoint元素的完整格式如下所示：

```json
	"PathPoint": 
	[
		{
			"costs": [1, 2],
			"name": "p5712",
			"pose": "-6123 674 0",
			"vertex": "p5718 p7302",
			"postures": "F::HF F:HF:HF",
			"connections":
			[
				{
					"name":"p5718",
					"cost":1,
					"posture": "F::HF",
					"type":1,
					"x1":-1200,
					"x2":-1200,
					"y1":0,
					"y2":0
				},
				{
					"name":"p7302",
					"cost":2,
					"posture": "F:HF:HF",
					"type":1,
					"x1":-1200,
					"x2":-1200,
					"y1":0,
					"y2":0
				}
			]
		},
		{
			"costs": [1, 1, 1],
			"name": "p5718",
			"pose": "-6123 1274 0",
			"vertex": "p5712 p5724 p7308",
			"postures": "F::HF F:HF:HF",
			"connections": [...]
		}
	]
```
