## 机器人使用说明
### 车体
#### 碰撞条
碰撞条位于车的前方，如下图：
![碰撞条](/单机/机器人使用说明/collision-bar.jpg)
当碰撞条受到压力（比如用脚踢一下碰撞条），小车会进入软急停状态，使能被关闭：
![软急停](/单机/机器人使用说明/stop-mode.jpg)
#### 急停按钮
本体一般都有两个急停按钮，一个在车前方，一个在车后方：
![急停按钮](/单机/机器人使用说明/estop.jpg)
按下按钮后小车会进入急停状态，急停按钮不会自动弹起，需要按方向旋转按钮来关闭急停：
![急停按钮](/单机/机器人使用说明/estop-top.jpg)
急停按钮抬起后，小车依旧处于软急停状态，需要开启使能才能正常行驶
#### 使能启用
开启使能有两种方式，第一种是通过点按Juion Manager上的使能按钮：
![使能](/单机/机器人使用说明/enable.png)
第二种方式是长按小车上的开机键（绿色按钮）来启用使能：
![开机](/单机/机器人使用说明/green-button.png)
#### 推动
在急停后推动小车需要按住小车背后的黄色按钮才能推动小车：
![黄色按钮](/单机/机器人使用说明/yellow-button.png)
#### 充电
充电桩如下图所示：
![充电桩](/单机/机器人使用说明/dock.jpg)
将小车背后的充电口对准充电桩的接口，慢慢推入后即可充电

### JunionManager
#### 链接
- 单个连接  
	`视图`->`连接`，弹出如图所示的`Add Robot`对话框，输入IP地址、用户名、密码、端口号，点击`确认`即可连接上AGV
	![连接单个AGV](/单机/机器人使用说明/连接单个agv.png)
- 批量连接  
	`视图`->`批量连接`，在弹出的对话框中选择编辑好的AGV账号文件，即可批量连接上AGV
	![批量连接AGV](/单机/机器人使用说明/批量连接agv.png)
#### 使用
- **断开**：断开当前选中的机器人  
- **充电**：给当前选中的机器人发送充电的命令，机器人会自动寻找最近的充电点去充电
- **空闲**：停止当前选中机器人的操作，并令其处于空闲状态
- **停止**：停止当前选中机器人的一切操作  
- **路径**：用于控制是否在实时场景区显示当前选中机器人行走时的路径 
- **激光**：用于控制是否在实时场景区显示当前选中机器人的激光点 
- **使能**：用于控制当前机器人的驱动器，未选中表示AGV软急停
- **位姿**：是否显示坐标信息
- **安全**：是否开启雷达安全检测  
![AGV地图显示相关](/单机/机器人使用说明/agv地图显示相关.png)
- **IO**：弹出一个面板，显示当前机器人的输入输出状态，并且可以通过按钮给机器人发送输出信号  
![IO](/单机/机器人使用说明/io.png)
- **定位**：给机器人发送重新定位的命令，选中后鼠标会变成十字，在实时场景区选定位置后按住鼠标拖动指定方向，松开后机器人会定位到该位置
- **居中**：在实时场景区中居中显示当前选中的机器人
- **发送位置**：操作与定位类似，指定好实时场景中的位置后，会将该位置发送给机器人，使机器人自动行走到该位置
- **下载地图**：从当前选中的机器人下载地图，并且更新实时场景区
- **更新配置**：发送命令给机器人，让机器人重新加载自己的参数
- **旋转**：用于将实时场景进行顺时针旋转 90°
#### 任务
右键`Routes`->`key`，点击执行  
![Routes执行](/单机/机器人使用说明/routes执行.png)
#### 模式
- Drive：手动驾驶模式  
![手动驾驶](/单机/机器人使用说明/手动驾驶.png)
- Stop：停止状态
- Idle：空闲状态

### 地图
#### 扫图
点击`视图`->`环境扫描`，弹出环境扫描小窗口，输入扫描后保存名称后点击`确认`  
![扫图](/单机/机器人使用说明/扫图.png)
确定后，手动操作AGV沿着环境周边运行一周后点击`停止`按钮  
![停止扫图](/单机/机器人使用说明/停止扫图.png)
#### 建图
点击`视图`->`创建地图`，弹出Create Map小窗口，输入扫描后保存名称和选择AGV类型后，点击确认  
![建图](/单机/机器人使用说明/建图.png)
建图开始时弹出cmd窗口，并显示建图进度  
![建图进度](/单机/机器人使用说明/建图进度.png)
待建图完成后，在安装目录下的/files文件夹下可以找到对应的.pgm文件  
![建图完成](/单机/机器人使用说明/建图完成.png)
#### 编辑地图
点击`编辑`，然后快捷键`Ctrl+H`，会弹出`Load PGM Map`  
![编辑Load](/单机/机器人使用说明/编辑load.png)
然后选择刚刚建图完成的.pgm文件，点`打开`  
![编辑打开](/单机/机器人使用说明/编辑打开.png)
编辑界面会出现刚刚绘制好的地图的底图，首先选择到`图1底层`，之后可以左右拉下旋转的条幅进行旋转底图到正常的、适合观看的角度  
![编辑旋转](/单机/机器人使用说明/编辑旋转.png)
之后可以根据实际需求添加起点、目标点等点位信息。绘制好底地图后，可以直接上传地图，也可以保存地图后加载地图

#### 类型/结构
- **设备参数**
	- 激光/相机  
		激光和相机的主要参数有`camera`,`dp_cam`,`laser`,`laser_back`,`laser_top`等。激光和相机的参数主要是为了修改扫描范围、扫描精度以及安装位置等参数。详细参数见[urobot参数说明](/单机/机器人使用说明/urobot参数说明.v.3.50.45.pdf)中的2.2 主激光。另外需要修改bz_robot中的激光参数，详细参数见[bz_robot参数说明](/单机/机器人使用说明/bz_robot参数说明.pdf)中的moudule/robot/sensor。
	- 机器人  
		目前修改机器人参数需要[直接修改](#bz_update)bz_robot的参数，例如机器人的避障大小，速度和加速度等。详细参数见[bz_robot参数说明](/单机/机器人使用说明/bz_robot参数说明.pdf)中的module/safety和module/tracker。
- **算法参数**  
	目前在Junion Manager中直接修改的算法参数不会生效如`loc`,`map`,`nav`,`plan`。需要[直接修改](#bz_update)bz_robot的参数。可修改的参数包括地图参数：地图分辨率，障碍物相关的配置等；路径规划参数：a*规划，拓扑路线规划，拓扑节点规划，混合规划等；路线平滑参数：b样条平滑器，梯度下降平滑器，射线平滑器，控制预测平滑器等。详细参数见[bz_robot参数说明](/单机/机器人使用说明/bz_robot参数说明.pdf)中的module/map，module/plan和module/smoother。
- **安全参数**  
	安全参数是任务参数的额外参数，在执行每种任务的时候都会读取对应的安全参数，详细的任务参数见routes中的[常用参数](#task_params)。目前在Junion Manager中修改可生效的只有`task-avoid`避障参数，其中以`clearance`为前缀的参数为避障框的大小，避障框大小为动态的，和机器人的速度相关，避障框相关的最大和最小速度由`clearance_slow_vel`和`clearance_fast_vel`决定。`enable_sonar`决定是否启用声纳，`ignore_from_when_forward`和`ignore_from_when_backward`决定了机器人在前进或后退时是否忽略相反方向障碍物的起点位置，`use_forbidden`和`use_estop`决定了是否使用地图中的禁用线和是否允许使用急停。  
	除`task-avoid`外的剩余参数需要[直接修改](#bz_update)bz_robot的参数，如`task-goto`和`task-clean`等。详细参数见[bz_robot参数说明](/单机/机器人使用说明/bz_robot参数说明.pdf#16)中的task目录。
- **其他参数**  
	主要指info参数模块，info中有多个与设备、任务相关从参数块，分别为：
	- *dock*: 充电相关参数
	- *io*: input/output相关参数
	- *key*: 9格键盘相关参数
	- *network*: 网络相关参数
	- *socket*: socket-mode相关的参数
	- *sound*: 声音控制相关参数  <br/>
	另外，info中会涉及到比较简单的任务调用功能，任务调用的命令格式有两种：  
	- *task:command*: 固定的命令，如`task:charge`表示执行自动充电任务，`task:idle`表示切换到空闲状态
	- *routes:name:key*: 执行routes中国某个路线任务，如`routes:Test:a`表示执行`Test`路线任务，从`a`这个子任务开始。  <br/>
	详细的参数说明见[urobot参数说明](/单机/机器人使用说明/urobot参数说明.v.3.50.45.pdf)中的5 补充参数。
### Routes
#### 编辑逻辑
每个Routes都是由许多一系列子任务以json形式串联成的一个复杂任务，通过key来分辨任务。如下列示例：
```json
{
    "test_A": {
			"a": {
				"cmd": "goto",
				"goal": "A",
				"max_vel": 1000,
				"target": "goal"
			},
			"a1": {
				"back_times": 3,
				"cmd": "tag",
				"distance": -600,
				"note": 1,
				"offset": 500,
				"odom_dis": 500,
				"online_dis": 400,
				"speed": 120,
		  },
		  "a10":{
				"cmd":"a1"
		  },
		  "a11": {
				"cmd": "wait",
				"note": 1,
				"time": 8
		},
		  "a111": {
				"cmd": "move",
				"distance": -2000,
				"speed": 200
		}
	}
}
```
其中`test_A`为这个为route名称，`a`、`a1`等为任务的key。在这个route开始执行的时候key会是`a`，在`a`对应的任务执行完成后会有一个返回值，假设返回值为1，那么下一个要执行的任务将会是当前key和返回值拼接的新key`a1`对应的任务。在上列示例中`a1`对应的`tag`任务在执行完后可能会有0或1两个返回值，执行完任务后如果返回的是1，那么下一步执行的任务为`a11`，如果返回的是0，那么下一步执行的任务会是`a10`。当route中没有要执行的任务的key时，整个route执行完成。
<a id="task_params"></a>

#### 常用参数
route中的每个任务都有一个`cmd`字段来指定当前任务的类型，以下是一些常用的`cmd`:
- 简单任务  
    - ***map***  
		切换机器人正在使用的地图，通过name和path来指定地图，加载成功返回1，否则返回0，route示例如下：
		```json
		{
			"a11": {
				"cmd": "map",
				"name": "01.json",
				"path": "/home/map/01.json"
			}
		}
		```
    - ***input/output***  
		input任务机器人会在原地等待IO触发任务跳转，output设定则是用来控制电机或其他设备，示例如下：
		```json
		{
			"a": {
				"cmd": "output",
				"target": "all",
				"flags": "X01X,XXXX,XXXX,XXXX,XXXX,XXXX,XXXX,XXXX"
			},
			"a1": {
				"cmd": "input",
				"target": "all",
				"flags": "X01X,XXXX,XXXX,XXXX,XXXX,XXXX,XXXX,XXXX",
				"time": -1,
				"flag": "1",
				"position": "30",
				"note": "1"
			}
		}
		```
    - ***sensor***  
		用于开启或者关闭传感器，可控制的有主激光、侧激光和声纳，示例如下：
		```json
		{
			"a": {
				"cmd": "sensor",
				"main_laser": true,
				"side_laser": true,
				"sonar": false
			}
		}
    - ***socket***  
		用于和外部进行TCP socket通信，需要指定ip、端口、通信内容和链接总时长，示例如下：
		```json
		{
			"a111": {
				"cmd": "socket",
				"ip": "172.10.21.238",
				"note": 1,
				"port": 12001,
				"send": "$~cmd:start|type:code|mode:once|index:1|color:0|width:640|height:480~$",
				"time": 10
			}
		}
		```
    - ***sound***  
		用于播放提示音或者控制背景音乐，有四种模式，示例如下：
		```json
		{
			"a11": {
				"cmd": "sound",
				"record": "excuse",
				"target": "record"
			}
		}
		```
- 移动任务
    - ***curve***  
		通过设定线速度`v`和角速度`w`使机器人按照弧线移动，示例如下：
		```json
		{
			"a": {
				"cmd": "curve",
				"distance": 3140,
				"v": 300,
				"w": 17
			}
		}
		``` 
    - ***drive***  
		用于手动控制机器人，按照线速度`trans`和角速度`rot`移动，超过两秒没有接收到速度机器人就会停止移动，示例如下：
		```json
		{
			"a1": {
				"cmd": "drive",
				"trans": 300,
				"rot": 20
			}
		}
		```
    - ***head***  
		控制机器人转向，通过角速度`speed`和最终角度`angle`来控制机器人的移动，angle为正则逆时针旋转，为负时顺时针旋转，示例如下：
		```json
		{
			"a11": {
				"cmd": "head",
				"angle": 90,
				"speed": 10
			}
		}
		```
    - ***move***  
		用于控制机器人前后移动一段距离，必须规定`distance`距离和`speed`线速度，前后方向可以通过`distance`的正负来控制，示例如下：
		```json
		{
			"a111": {
				"cmd": "move",
				"distance": 2000,
				"speed": 300
			}
		}
		```
    - ***reflector***  
		用于对接反光板，`distance`时对接结束时激光距离反光板中心的前后距离，`gap`是两块反光板中心的间距，`offset`是对接结束时激光距离反光板中心左右的偏移距离，正数为偏右，负数为偏左，示例如下：
		```json
		{
			"a1111": {
				"cmd": "reflector",
				"distance": 100,
				"gap": 500,
				"offset": 0
			}
		}
		```
- 导航任务
    - ***loc***  
		用于机器人重定位，参数是定位点，`target`可以是目标点`goal`或者是坐标`pose`，以下是目标点示例，坐标点示例见`goto`任务:
		```json
		{
			"a": {
				"cmd": "loc",
				"goal": "A",
				"target": "goal"
			}
		}
    - ***goto***  
		自主导航到坐标或目标点，同`loc`任务，`target`有两种方式，指定坐标时必须指定`x`和`y`，`th`为可选项，是指定机器人到达坐标后的角度。有一些可选项：`max_vel`最大线速度，`turning_radius`旋转半径，`times`表示允许全局重新规划的次数，`-1`表示不限制，`time`表示去往目标点的最大时长，示例如下：
		```json
		{
			"a1": {
				"cmd": "goto",
				"x": 19012,
				"y": 27634,
				"th": 90,
				"target": "pose",
				"max_vel": 1500
			}
		}
		```
    - ***rms_goto***  
		作用和参数同goto指令，区别在于rms_goto需要RMS服务器统一规划路径，示例如下：
		```json
		{
			"a11": {
				"cmd": "rms_goto",
				"goal": "B",
				"target": "goal"
			}
		}
		```
    - ***go_ref***  
		融合了goto和reflector的任务，包含了所有goto和reflector的参数，除此之外还要添加在目标点多大范围内进行过程切换的参数：`goal_front`，`goal_side`，`goal_rear`这三个参数结合表示在目标点前、侧、后方的范围距离，进入范围开始找反光板，当机器人朝向误差小于`goal_angle_tol`设定的范围时，切换到对接过程。`ref_center_robot`用来设定机器人是否判断两块反光板是否超出左右范围，示例如下：
		```json
		{
			"a111": {
				"cmd": "go_ref",
				"goal": "B",
				"target": "goal",
				"distance": 100,
				"gap": 500,
				"offset": 0,
				"goal_front": 100,
				"goal_side": 100,
				"goal_rear": 100,
				"goal_angle_tol": 10,
				"ref_center_robot": false
			}
		}
		```
    - ***charge***  
		用于机器人充电，`goal`为`auto`时机器人主动寻找直线距离最小的充电桩去充电，充电任务还包含了task中指定的卡住后的处理参数，见`task-reflector`和`task-dock`参数说明，示例如下：
		```json
		{
			"a1111": {
				"cmd": "charge",
				"goal": "Dock1",
				"target": "goal"
			}
		}
		```
#### 模板
`routes.template.json`是模板文件，需要配合`routes.params.json`文件来使用，这两个文件位于`/urobot/params/routes`文件夹下。模板的存在是为了减少大量重复的routes编写，对于流程固定但只有几个参数不同的routes就可以编写成模板，观察如下示例：
```json
{
    "JT-N": {
        "a1": {
           "back": true,
           "cmd": "jump",
           "key": "a",
           "note": 1,
           "routes": "$Speed-type"
        }
    }
}
```
其中模板名称为JT-N，其中a1指令中`routes`的值带着`$`符号表示这个值为一个变量，变量名为`Speed-type`，在应用模板的时候需要给这个`Speed-type`赋值。观察下列`routes.params.json`的示例：
```json
{
    "ZB01-DJJD-N": {
			"$shelves-type": "shelves-TH",
			"$Speed-type": "set_pull_JT_params",
			"$Target": "ZB01",
			"$Target1": "ZB01-DJJD",
			"$turntable-angle": 0,
			"$ref-dis": 180,
			"$online_dis": 40,
			"$online_distance_to_stop": 2500,
			"$ref-gap": 400,
			"$ref-offset": 0,
			"template": "JT-N"
	}
}
```
这个routes的名称为`ZB01-DJJD-N`，应用的模板为`JT-N`，其中`$Speed-type`的值会被填入模板中value为`$Speed-type`的地方，最终形成的routes如下：
```json
{
    "ZB01-DJJD-N": {
        "a1": {
           "back": true,
           "cmd": "jump",
           "key": "a",
           "note": 1,
           "routes": "set_pull_JT_params"
        }
    }
}
```

### 单机部署
#### 目录/模块
urobot的大致路径如下：
```
urobot
├── bin
│   └── urobot
├── bot_log
├── bz_robot
│   ├── bin
│   │   └── bz_robot
│   └── scripts
├── jarvis
│   ├── bin
│   ├── include
│   ├── lib
│   └── share
├── log
├── logs
├── lua_scripts
├── params
│   ├── algo
│   ├── bz_robot_params
│   ├── device
│   ├── map
│   ├── routes
│   └── service
├── resource
└── upgrade
```
其中比较重要的部分有bz_robot，jarvis，params，resource  

- ***bz_robot***: 规划控制的模块
- ***jarvis***: 单机交互的模块
- ***params***: 参数文件
- ***resource***: 一些资源文件比如音频等
#### 参数文件
所有的参数文件都位于params文件夹下面
- ***algo***: 算法模块的相关参数
- ***bz_robot_params***: 规划控制模块的相关参数，机器人的最大速度，最大加速度等都在这里设置
- ***device***: 设备相关参数
- ***map***: 地图相关参数
- ***routes***: 所有单机的routes参数，routes的模板文件也位于此
- ***service***: 单机的服务参数，其中info、rms、service等参数文件都位于此文件夹下
#### 服务相关
启动和关闭服务：
```bash
sudo systemctl start urobot
sudo systemctl stop urobot
```
