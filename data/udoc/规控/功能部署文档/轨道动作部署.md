## 一、概述
该文件描述了不使用plc机构的机器人在需要运行轨道动作所使用的routes的选择和参数配置，并介绍了各阶段可能出现的问题和处理方法。
这里的选择有两个：
1. opc
	opc是在进行一系列轨道动作的同时还会与机台，rms进行通信。仅在有opc的现场进行使用。轨道的转停同时有下位机和opc规定。
2. settrack
	settrack是不和opc进行通信，执行routes就会开始转，下位机认为到位后就会停止转动执行下一步。

## 二、routes模板
```
opc:{
  "a" : 
  {
    "cmd" : "opc",
    "confirm" : false,              //是否要与rms通信
    "Light_color" :"GreenStanding", //轨道动作中的灯光状态
    "ip" : "172.10.15.106",         //opc ip
    "timeout":2000,                 //opc心跳超时时间
    "port" : 34339,                 //opc 端口
    "laser_to_machine_dist": 1000,  //激光前方多少距离需要有障碍物
    "target" : "110030311",         //任务号
    "track1" : "PUT",               //轨道1的动作
    "direction1":"HEAD",						//轨道1的传输方向，仅轨道两边均可传料时使用
    "track2" : "OFF",               //轨道2的动作
    "direction2":"HEAD",						//轨道2的传输方向，仅轨道两边均可传料时使用
    "track3" : "OFF",               //轨道3的动作
    "direction3":"HEAD",						//轨道3的传输方向，仅轨道两边均可传料时使用
    "track4" : "OFF"                //轨道4的动作
    "direction4":"HEAD",						//轨道4的传输方向，仅轨道两边均可传料时使用
  }
}

settrack:{
  "a":{
    "cmd": "settrack",
    "track1": "stop",
    "direction1":"HEAD",						//轨道1的传输方向，仅轨道两边均可传料时使用
    "track2": "put",
    "direction2":"HEAD",						//轨道2的传输方向，仅轨道两边均可传料时使用
    "track3": "get"
    "direction3":"HEAD",						//轨道3的传输方向，仅轨道两边均可传料时使用
  }
}

```

## 二、OPC各阶段参数说明  
opc用于不使用plc且现场存在opc的轨道动作部署。不存在opc请使用settrack
### 1.连接opc  
opc无法连接时会报错。报错内容为:  
OPC, Failed connect to (ip:port)  
相关参数：
|参数名|作用|
|:---:|:---:|
|ip|所用opc的ip|
|port|所用opc的端口| 

### 2.初始化激光测距  
需要在激光范围一定距离内存在障碍物，否则任务失败。目的是防止卡料导致机器人位置偏移使得后续任务受影响。  
可能报错内容为:  
ModeOPC, start laser measure failed.  
ModeOPC, laser to machine too far  
相关参数:
|参数名|默认值|作用|
|:---:|:---:|:---:|
|enable_laser_measure|true|是否启动激光测距功能,参数位置在rms.json中|
|laser_to_machine_dist|1000|激光测距距离|

### 3.连接rms获取对应的轨道动作或取消任务  
可能报错内容为:  
连接超时：ModeOPC, connect to rms(ip:port) failed(>30s)  
任务取消：ModeOPC, task has been cancelled by rms.  
相关参数:
|参数名|默认值|作用|
|:---:|:---:|:---:|
|confirm|true|是否需要连接rms|

### 4.轨道动作处理
作用为避免空车送料或满车接料的情况  
可能报错内容为:  
轨道动作全为off：ModeOPC, params invalid, all tracks are off.  
空车送料：ModeOPC,track, need put, but found sensor is 0.  
满车接料：ModeOPC,track, need get, but found sensor is 1.  
相关参数:
|参数名|默认值|作用|
|:---:|:---:|:---:|
|trackn|OFF|轨道n的动作，n可为1-4.参数值可以是OFF,PUT,GET|
|direction|HEAD|轨道n的方向，适用于支持双向传料的轨道.参数值可以是HEAD,TAIL|
|track_sensor_count|2|需要几个光电数据才会认为有料，现在一般需要设置为1.参数位置为rms.json|


### 5.连接topcore  
可能报错内容为:   
未配置虚拟topcore：AgSerial: topcore, Send: connect error.
相关参数:
|参数名|默认值|作用|
|:---:|:---:|:---:|
|has_topcore|false|是否使用虚拟topcore，参数位置在params.json|

## 三、其他参数说明  
|参数名|默认值|作用|
|:---:|:---:|:---:|
|enable|false|是否使用机台机台，参数位置为device/opc.json|
|light_color|"OrangeStanding"|传输过程中三色灯颜色，可选值有"AllOff","RedStanding","RedBlink","GreenStanding","GreenBlink","OrangeStanding"，"OrangeBlink"|
|need_open_charge_circuit|false|是否打开充电回路,用于传料时需要充电的场景|
|check_charging_signal|false|同上|
|target|""|通常为任务号|
|timeout|3000000|opc心跳超时时间|
|heartbeat_interval|-1|opc心跳包发送频率参数位置为device/opc.json|
